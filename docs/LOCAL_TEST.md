# 本机验收

目标是确认真实电脑能发现并执行这个版本。不要重复开展大规模创意测试。不把开发环境的文件检查当成本机验收。

## 后续新环境的最小交接

同机项目级与默认用户级Codex生命周期已有结果，不为准备交接重复运行。下一轮先具备可实际执行的Claude环境，或另一台目标机器/系统；在同一台Mac换临时目录不算跨机器验证。

1. 记录目标系统、宿主版本、安装范围和本轮要验证的能力。安装使用公开v0.1.0包并核对[安装说明](INSTALL.md)中的摘要；需要升级/回退时使用已公开rc2与v0.1.0，不夹带开发运行规则。
2. 启动宿主前检查项目级和用户级同名目录及失效链接，记录已有安装和相关技能根目录的基线，包括宿主可能自动刷新的内置系统文件。已有安装不覆盖；测试自有目录与完整备份分开，备份放在技能发现根目录之外。出现非预期变化先停止并核实恢复。
3. 在独立项目用新会话实际发现、读取安装入口与参考并核对摘要，再记录安装、升级、回退、卸载各阶段。仅复制文件不能证明宿主已加载；卸载后检查测试条目消失、已有安装和基线恢复，不能只检查测试目录被删除。
4. 先做第1、2节的只读/文字验证。第3、4节的生图和编辑另按实际工具能力与授权执行；不可用或未执行明确记录，不写成通过。日志、完整备份和账号信息只私有保存，对外摘要仅写实际环境、步骤、结果与限制。

真实新用户首用可沿用现有[问题反馈模板](../.github/ISSUE_TEMPLATE/bug_report.md)，记录卡在哪一步及实际表现；尚无参与者时不把维护者自测算成新用户反馈。搜索收录另需对应搜索结果或站长平台证据，不与安装验收混记。

## 1 安装与能力

按README安装后，打开一个新任务。记录：操作系统、宿主名称/版本、实际加载的Skill位置、是否存在同名旧版本，以及能否读本地图、传图、生图、编辑和保存输出。按v0.1.0正式包范围将实际安装目录中的11个运行文件与本包逐项比较（不含源侧evals/CHANGELOG），再确认新会话实际读取的入口和参考；同名不代表同版本。若宿主附加界面元数据，记录差异并确认主流程与参考正文一致。公开记录使用项目相对路径或用户目录缩写，不包含个人目录全路径、账号或密钥。

分别记录“可读商品图”和“生图工具能实际接收商品图”，两者不能互相代替。没有生图工具时，先停在文字模式，记录“本机生图阻塞：能力不可用”。只有文字生图、不能输入参考图时，仍可做方案，但此保真验收不进入第3步；没有编辑能力时，第4步记为阻塞，不能用文字重新生成冒充编辑。不要自动安装依赖、使用浏览器或切换付费API来凑通过。

## 2 先看方案

上传 `examples/clothespin-public-domain.jpg`，发送：

> 使用 $create-miniature-world，把前景的浅色木夹做成微缩摄影。保持商品外观，人物很小。先给三个方案，不要生图。没有人偶实物参考时请明确说明。

检查：读对前景商品；没有把手指或背景夹子变成产品；方案各有可见联系；未提前生图。用户可以选择任一方案，不要求复述历史故事。

## 3 实际生成

仅在用户授权图像调用、工具支持参考图输入时执行；只检查安装或要求“不生图”时不进入此步。选择方案后发送：

> 用我选的方案生成一张，竖版3:4，产品别改。先只生成一张，不要自动追加修正。把结果另存到当前项目的outputs目录，原图不要覆盖。

检查实际输出能打开、实际宽高为3:4、商品图确实作为输入传入工具；原物可辨认；看得见关键关系和支撑；小人不过大；记录商品和故事未通过之处。保留本次实际提示词、输入角色与相对文件路径，便于区别策划问题和生成偏差，不需要另建日志系统。若严格匹配人偶，先上传有权使用的实物参考，再生成。没有参考的成图不能写成Preiser实物匹配通过。

## 4 一句反馈修改

仅在用户授权编辑且工具具备实际编辑能力时执行；安装文字验证不自动进入此步。发送：

> 光线暖一点，其他不变。只编辑当前这张并生成一个结果，不自动追加修正；另存新文件。

检查：实际执行编辑；构图、商品、人物数量和位置没有明显无关变化；修改图与首图各自保存。生成式编辑可能改变微小纹理，不要求逐像素一致，但不能掩盖明显结构改变。
