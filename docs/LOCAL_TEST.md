# 本机验收

目标是确认真实电脑能发现并执行这个版本。不要重复开展大规模创意测试。不把开发环境的文件检查当成本机验收。

当前状态（2026-10-09）：Codex 宿主的本机流程已按第 3、4 步走通（见第 5 节结果表与 [2026-10-05 本机审计](LOCAL_AUDIT_2026-10-05.md)）；Claude Code 宿主尚未安装、未验收；任一样张的严格商品保真均未判通过。新环境仍按下表逐项验收。

## 1 安装与能力

按README安装后，打开一个新任务。记录：操作系统、宿主名称/版本、实际加载的Skill位置、是否存在同名旧版本，以及能否读本地图、传图、生图、编辑和保存输出。将实际加载目录中的SKILL.md、references/creative-relations.md、agents/openai.yaml与本包逐项比较；同名不代表同版本。若宿主附加界面元数据，记录差异并确认主流程与参考正文一致。公开记录使用项目相对路径或用户目录缩写，不包含个人目录全路径、账号或密钥。

分别记录“可读商品图”和“生图工具能实际接收商品图”，两者不能互相代替。没有生图工具时，先停在文字模式，记录“本机生图阻塞：能力不可用”。只有文字生图、不能输入参考图时，仍可做方案，但此保真验收不进入第3步；没有编辑能力时，第4步记为阻塞，不能用文字重新生成冒充编辑。不要自动安装依赖、使用浏览器或切换付费API来凑通过。

## 2 先看方案

上传 `examples/clothespin-public-domain.jpg`，发送：

> 使用 $create-miniature-world，把前景的浅色木夹做成微缩摄影。保持商品外观，人物很小。先给三个方案，不要生图。没有人偶实物参考时请明确说明。

检查：读对前景商品；没有把手指或背景夹子变成产品；方案各有可见联系；未提前生图。用户可以选择任一方案，不要求复述历史故事。

## 3 实际生成

选择方案后发送：

> 用我选的方案生成一张，竖版3:4，产品别改。先只生成一张，不要自动追加修正。把结果另存到当前项目的outputs目录，原图不要覆盖。

检查实际输出能打开、实际宽高为3:4、商品图确实作为输入传入工具；原物可辨认；看得见关键关系和支撑；小人不过大；记录商品和故事未通过之处。保留本次实际提示词、输入角色与相对文件路径，便于区别策划问题和生成偏差，不需要另建日志系统。若严格匹配人偶，先上传有权使用的实物参考，再生成。没有参考的成图不能写成Preiser实物匹配通过。

## 4 一句反馈修改

发送：

> 光线暖一点，其他不变。只编辑当前这张并生成一个结果，不自动追加修正；另存新文件。

检查：实际执行编辑；构图、商品、人物数量和位置没有明显无关变化；修改图与首图各自保存。生成式编辑可能改变微小纹理，不要求逐像素一致，但不能掩盖明显结构改变。
