# 上传一张商品照，怎样做微缩摄影

本教程用2026-10-14真实遥控器实测演示v0.1.0的用法。它展示操作路径和结果限制；原照及两张After见[实测案例](../examples/REMOTE_CONTROL_TEST_20261014.md)，网页排版见[图文教程](../site/remote-control.html)。

## 1. 安装，然后上传清楚的商品照

先按[安装说明](INSTALL.md)安装Skill。在Codex或Claude Code会话中上传你有权使用的照片：完整主体、按键、标识和屏幕尽量清楚。有关键的背面或内部结构，按需要补图；没有时保持未知。网站只是说明页面，上传和生成在你的助手会话中进行。

这次照片显示一台旧白色格力空调遥控器，屏幕26°C、中文按键、冷热键颜色、环形结构和磨损可见。照片中的桌面可以作为背景处理，商品本体的可见细节默认保留。

## 2. 用一句话开始

先看方案、控制调用数量时：

**Codex**

```text
使用 $create-miniature-world，把这张遥控器做成微缩摄影。先给三个不同的短方案，推荐一个，暂不生图。保留屏幕显示、按键数量与排列、中文标识、颜色和旧痕。
```

**Claude Code**

```text
/create-miniature-world 把这张遥控器做成微缩摄影。先给三个不同的短方案，推荐一个，暂不生图。保留屏幕显示、按键数量与排列、中文标识、颜色和旧痕。
```

选定后发送“按方案1生成一张，使用默认田中风格”。也可直接说“创意你来定，生成两张让我挑选”；默认推荐案和次选案各一张，仍依赖当前宿主的真实生图能力。只要方案或提示词时明确说不生图。Claude Code现有验证覆盖方案输出，没有内置生图；需要把得到的提示词和有权使用的参考图交给支持图像输入的工具，不声称已生成。

上面是方便复用的教程示例，**不是本次用户实际发送的完整原话**。本次用户先请求拿照片测试，再明确选择“实际生成两张，测试参考图保真”；助手自行构思并生成“降温要全队出动”和“节能环岛”。[实际调用提示](../examples/prompts/remote-control-20261014.json)另存，不把示例当作已跑过的对照实验。

## 3. 看结果，也对照原照

两张结果均采用田中风格：米白卡纸、偏暖柔光、完整商品和很小的人物；人偶涂装实际参考包内实拍。原图与后期应分别保存，后期只加颗粒或轻微虚化。

分别检查商品外观、故事与接触、人物尺度、美感。此例整体和主要按键可辨认，但第一张多出雪花图标，两张都有字形、键形或磨损重绘；第二张四段弧键不能直接当成连续道路。**不能因为画面漂亮或遥控器能认出，就判严格保真通过。** 此例原照与两张后期版获准公开，四维质量尚未获得用户通过反馈。

## 4. 用具体反馈继续

例如：

```text
修改第一张：去掉屏幕中新增的雪花图标，恢复为原照片的屏幕状态。人物、商品、背景和光线保持其余已确认部分不变。
```

```text
第二张换一个不需要连续道路的创意，保留遥控器原来的按键结构，先给我文字方案，不生图。
```

这些是后续沟通示例，本次没有执行。编辑需要当前工具真正支持，并重新对照原照；不能仅凭“已修复”的文字认定修好。

想看另一种拍法时可以说“沿用已选故事和人物布局，生成一张实拍光影版”：单一光源、微距浅景深、明显亮暗。此例没有生成这条路线，当前两张比较的是创意。风格对照仍是生成过程，商品及人物可能变化，不能保证只有光线发生变化。

## 素材与能力边界

参考图会传入实际生图工具。仅使用有相应权利的素材，公开案例需另有公开授权；本教程使用用户本次明确授权的三张图。照片及AI成图不自动适用代码MIT，也不认证准确SKU、屏幕状态、全部文字或Preiser型号。许可与逐文件摘要见[案例记录](../examples/REMOTE_CONTROL_TEST_20261014.md)和[素材说明](../THIRD_PARTY_NOTICES.md)。
