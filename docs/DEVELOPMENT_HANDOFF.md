## 目标、范围与当前状态

用户希望微缩造景Skill能在本机使用，后续开源到GitHub。已经经历多轮真实样张与用户反馈，不应从零重新做风格研究。当前优先级是接通实际运行并验收一次闭环；用户明确不要过度工程化。

核心方法：发现联想，找到商品值得被重新看见的特征；建立情境，让行动或空间关系把联想显现；组织画面，让原物、新角色和美感共存；判断巧思，用可见证据区分成立、好看与保真。故事不必演示商品功能，但需要可感知的物件联系，也不必有冲突或结局。

本包是可移植源文件快照，不含完整聊天、全部研究文件、历史图片或完整Git历史。核心方法与历史反馈摘要已在参考文件中。不要把未附带的材料称为丢失，也不要宣称已恢复全部开发档案。

已完成的检查、文字试用、rc2修正和未验证项以[VALIDATION.md](VALIDATION.md)为准。当前私有开发仓库为 https://github.com/denggui-ai/create-miniature-world ，正式Release尚未发布。

## 先核对工具，再决定怎样测试

分别确认：读取本地商品图、把图片实际传入生图工具、生成、编辑指定成图、查看结果、保存文件。Claude接手代码不会自动获得原ChatGPT会话的图片工具、额度、登录状态或历史附件。

| 实际能力 | 本轮能做什么 | 不能据此宣称什么 |
| --- | --- | --- |
| 读图与文字策划 | 识别商品、三选案、输出提示词、审查用户返回的图片 | 已生图或完成端到端自动化 |
| 只有文字生图 | 用户明确接受时可做自由创作概念；严格商品保真任务先保留方案 | 商品参考图已输入或准确恢复标签 |
| 支持参考图的生成 | 生成商品方案并看图判断；记录实际输入 | 已具备编辑能力或所有商品均保真 |
| 参考图生成、编辑和结果保存均可用 | 按LOCAL_TEST跑一次完整闭环 | 成图必然好看、故事必然被看懂 |

没有合适的图像工具时，继续做方案和提示词即可。可以由用户在现有生图工具里生成并将结果交回审图；记录为人工接力，不记为本机自动生图通过。不要为通过验收擅自接付费API、账号或浏览器。若后续决定新增图像执行渠道，只围绕实际需要做最小连接，不先造通用适配层。

## 缺失材料：哪些影响接手

| 材料 | 本包状态 | 是否阻塞当前开发 |
| --- | --- | --- |
| 核心Skill、参考方法、安装/验收/发布说明、许可证 | 已有 | 不阻塞 |
| 可再分发的真实商品输入 | 已有木夹子照片 | 足够做首次流程试用；不是成功模板 |
| 成功与失败案例的原图、成图配对 | 只有文字摘要，未附图 | 不阻塞安装；会影响视觉标准校准和历史复盘 |
| 各旧案例的完整提示词、参考图角色、实际工具参数、输出与反馈对应关系 | 未完整附带 | 无法精确重放旧试验，也不能做前后效果归因 |
| 用户希望匹配的人偶实物参考 | 公开包有来源、没有照片 | 普通创作可标造型待审；严格Preiser造型匹配需参考 |
| 本机宿主版本、图片工具能力、权限与实际验收结果 | 待本机采集 | 阻塞“本机自动生图已通过”的结论 |
| 全量聊天、研究报告、全部作者作品 | 未打包 | 不是当前接手前提，避免先搜集全集 |

视觉校准优先补最少的三组证据：一组用户认可的样张及其输入，一组用户否定的样张及其输入，一组真实商品的原图与对应成图。已有材料能兼任时无需重复。历史中便利贴复刻获认可、剪刀冰场被否定；但不能仅按模糊文件名或“第2张”自行匹配图片。

每组只需要记录：实际图片路径、模式/输入角色、提示词与参数（没有则记缺失）、用户原话及认可范围、仍未通过之处。先确保图与反馈对应，不能补写不存在的记录。可放在 `private-inputs/` 中一份简短说明里，不建立数据库。

Preiser照片与作者原作没有纳入公开包是有意的素材边界，不应直接补进公开仓库。私下提供用于合法参考和允许公开再分发是不同用途。新增材料按各自权限处理，用户上传不代表同意开源。

## 必须继承的反馈与判断边界

- 回形针曾被误认成水管：先保住物件识别线索，再判断故事；后续图获认可不等于所有回形针题材通过。
- 修正带放映曾有空间位置错误：题材逻辑通顺仍需核查真实画面中的朝向、接触、路径和承托。
- 人偶多次偏大、像玩偶：需要同时检查雕塑造型、人物相对商品的大小及景别。拉远不等于相对缩小；品牌词不能代替实物参考。1:64是项目规划值，不是作者或Preiser的统一比例。
- 便利贴需要仍像纸叠，盖被关系要在图中显现；认可的复刻不证明独立联想有效。
- 剪刀冰场被用户否定；眼镜镜片是用户提出的候选，并未因此验证。斜面不必硬套滑冰，先回到物件结构重新选情境。
- 用户说“不错”“有意思”只支持对应样张或创意；不自动代表商品标签、尺寸、型号与其他画面细节通过。

更完整的历史边界见参考文件与[案例摘要](../examples/README.md)。这里是交接摘要，不是本轮实际看图结论。

## 首轮任务：做小而完整

先简短报告当前状态、实际缺失材料和工具能力。保留现有创意流程，使用包内木夹照片，先给三个有可见联系的方案并等待用户选择；不要把它固定成跷跷板或攀爬场景。注意前景木夹由手指按开，移除手指后要重新判断开合与支撑。

用户选择后，能力足够就生成一张，再用一句反馈编辑一次。记录过程可用与视觉可交付两个结论；能力不足就停在相应步骤并说明，不扩建系统。只有复现出的具体失败才修当前步骤；每次修改说明问题证据、改动和实际验证范围。缺历史图片不妨碍先跑这次新试用，但新试用不能伪装为旧案例复测。

正式发布仍按PUBLISH.md条件执行；本次交接本身不意味着可以发布。修改保持一份源，保留候选包基线，不覆盖旧结果。
