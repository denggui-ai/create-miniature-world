# v0.2.0 · 一张图卡与两条制作路线

日期：2026-10-20。核心流程重做版，运行范围仍为11文件，4份参考文档全部换新；历史版本及附件保留。

## 本次变化

- 策划和拍摄是同一件事，写成一张图卡：相机在哪、看见哪三件东西；什么巨大；谁小、人高约等于哪个部件；物件哪个部位成了什么、从这个机位凭什么像；正在发生什么事、笑点是什么；不加什么。一段话写完再出图。
- 制作分两条路线：只有物件名或实物照不能当底图时直接生成；实物照能当底图（机位近而低、物件填画、承托面干净、柔光）时编辑实物照，原照保留，只添加小人与配件。生成器已证实不听的事（人偶精细度、清晰带、比例句、朝向）用参考图、底图和路线解决，不堆措辞。
- 看图先答两问（在发生什么事；像不像小人在巨大物件的世界里），取同类田中原作并排写三处最大差异，记商品保留项；交付只问一句“这是什么场景”，用户第一读是闸门，助手自评只作记录。
- 参考文档换成四份：图卡、制作路线、看图、20张田中案例卡。案例卡只记可见特征、读法、证据、取景、清晰带、相机、人偶与迁移条件，附作者站点原图地址作本机对照入口；不含图片，原作不复制、不传入生成器、不发布。
- 删除：手持级/桌面级景别映射、全景硬门槛、参与者上限、出图前报画幅、评图A–F与四类检查、“柔光棚拍 / 实拍光影”拍法名及旧4份参考文档（归档在开发仓库，安装时须删除）。保留：每案一张首图、编辑只在用户点名那张上至多一次、失败不重试、商品保真三模式、`photo_finish.py` 后期脚本（只在用户点名时用；默认 `--dof none`、`--grain 0`，即不开颗粒与虚化，虚化只按图像行不按景深）。
- 用户说了机位或景别时图卡第1条照办并照常过门槛；与“相机在场景里”冲突的正上方俯拍先说明再按用户；不主动问景别。画幅默认方幅，用户指定优先。

## 安装与核验

下载 `create-miniature-world-v0.2.0.zip` 和同名 `.sha256`，同目录执行：

```sh
shasum -a 256 -c create-miniature-world-v0.2.0.zip.sha256
```

先读[离线指南](USER-GUIDE.html)。本包为 **guide-required**；只安装 `skills/create-miniature-world/` 的11个运行文件。已有安装先完整备份到技能发现目录之外；从 v0.1.4 及更早升级时删除旧的4份参考文档（creative-method、photo-styles、figure-framing、creative-relations），不要与新4份并存。MANIFEST.json记录来源提交与逐文件摘要；校验值应来自可信渠道。源码eval、CHANGELOG、私有日志及本轮新图不入包，包内沿用已有许可与来源的历史刨丝器对照。

## 验证与限制

重做依据四路独立审计（两个外部模型与两个只读子代理，互不可见）对20张田中原作案例卡与本项目24个实发提示的交集结论：规则堆是次因，主因在底图、生成器重绘和想法与机位不匹配。源侧静态规范检查、兼容校验与8项后期测试通过；L3代码审查三轮收敛。

行为验证两条路线各1张。冰格（编辑实物照，像素差1.95%只落在近端格与扶梯）用户第一读“打扫卫生 应该是清理什么池子”，随后“我觉得这张不错的 可以通过”，记用户认可；刨丝器（直接生成）第一读“爬墙探索”，读法成立、未落在图卡事件，记候选。另两张直接生成（刨丝器高尔夫、回形针跨栏）第一读“高尔夫和跨栏比赛”与图卡一致，未判好坏。四张样张及冰格底图均不公开（底图为私有目录照，来源未核）。已知差距照旧：直接生成路线商品被重绘（孔形孔数变）、人偶偏精细、清晰带不稳。

Codex与Claude两套项目安装各11文件已核对；Claude宿主显式触发加载测试1次（只交图卡，未出图）。没有Codex新会话、盲测、跨机或桌面隐式触发验证；23条eval定义不等于23次执行；不宣称稳定成功率、生产就绪或全技能闭环自演进。发布阶段不追加生图或独立模型调用；发布检查的实际结果以维护者收据为准。
