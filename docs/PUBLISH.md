# GitHub发布

私有开发仓库已创建：https://github.com/denggui-ai/create-miniature-world 。尚未公开开源或发布正式Release。建议仓库名 `create-miniature-world`，首版在本机验收后发布为 `v0.1.0`；本候选包版本为 `v0.1.0-rc2`。

## 当前执行：私有开发仓库

用户已于2026-10-05授权先创建私有开发仓库并上传候选源，再在本机拉取验收。此步骤不等于公开开源或发布正式版本，不受下方正式版生图验收门槛阻塞。

先确认实际GitHub连接账户，再检查该账户下的同名仓库。新建时明确选择private；已有仓库先读内容和可见性，不覆盖、不强推、不擅自更改可见性。上传只包含已核对的项目源与文档，保留rc2待验收状态，不创建Release。上传后检查远端可见性与文件，再在README写入真实仓库地址。

私有仓库创建后，用户可在本机通过GitHub提供的真实克隆地址拉取，然后按README安装Skill。连接和权限不随ZIP传递，不将令牌写入文档或仓库。

## 正式发布前

1. 按LOCAL_TEST.md完成真实本机验收，使用相对图片路径记录证据。正式v0.1.0要求本机流程通过，且至少一张样张的商品保真、故事可读、人物尺度和美感得到实际看图确认；结果表填完不等于通过。存在失败、阻塞或待验收项时保留候选状态，不自动发布正式版；若以后明确选择公开实验版，应披露这些限制。
2. 确认所有公开文件在当前目录内；不要把私人研究目录或旧Skill素材文件夹一并复制进来。
3. 检查 `git status` 和将提交的文件：不含账号配置、密钥及整批输出缓存。精选商品图、人偶参考与案例图可以在核对来源、反馈对应及公开分发条件后纳入；不因其属于图片或品牌产品一律排除。`.gitignore`只是默认排除，不能替代查看实际文件。
4. 保留MIT及第三方素材说明。公开样张需另行核对来源和许可，并标明AI生成与已知缺陷。
5. 发布正式版时同步更新README与当前发布说明中的版本及状态；VALIDATION中的历史检查版本保留并补充新验证，不改写旧证据。创建仓库后再填真实URL；只在Release创建成功后标明已发布。

## 让本机Codex执行

本机验收结束后，可以在这个项目中发送：

> 阅读docs/LOCAL_TEST.md、docs/VALIDATION.md和本文件的发布条件，核对真实本机流程及样张是否通过，而不是仅检查表格是否填完。若通过，请整理改动并展示将公开的文件清单、许可证范围和已知限制，同步正式版文档状态，再用当前已授权的GitHub账号发布create-miniature-world仓库及v0.1.0版本。若仓库同名已存在，先检查内容，禁止覆盖或强制推送。若存在失败、阻塞或未验收项，明确指出并保持候选状态，不自动发布正式版。只有远端仓库与Release创建成功后，才报告完成并填入真实链接。

发布成功后，把真实仓库URL和安装路径写回README。不要提前写一个假定存在的链接。可提供仓库 ZIP 下载和指向 `skills/create-miniature-world` 的安装说明。

第一版只发布Skill和文档即可。官方文档建议通过插件分发跨平台可安装包；是否增加插件包装，等本机流程稳定后再决定，无需先建网站、服务端或MCP服务。
