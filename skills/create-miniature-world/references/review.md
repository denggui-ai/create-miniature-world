# 看图：两问、并排、谁来判

出图后先看整图，再看局部；先写看见了什么，再对照图卡。不用标题、职业或提示词替画面说话。

## 两问（任一答否，这张记失败，不选、不编辑）

1. **这张图里在发生什么事？** 只用画里看得见的参与者、动作、配件和环境线索回答。答不出，或只能说“一个人在做某动作”而这个人物本身不是一眼可读的段子，记失败。静态与无人作品答“这是什么地方、发生过什么”。
2. **像不像小人在一个巨大物件的世界里？** 三件一起看：人是物件的零头（人高≈图卡写的那个部件）；物件是真的（商品部件、文字、材质没被重画）；相机在场景里（近端大远端小，看见人的身侧和脚下的面，不是只见头顶的产品照）。缺一件就写明缺哪件。无人作品把“人”换成图卡写定的尺度参照物（车辆、配件、脚印、灯光）：参照物是物件的零头；物件是真的；相机在场景里（近端大远端小，看见参照物所在的面）。

## 与田中并排（每张都做）

从[田中案例](tanaka-cases.md)取同类物件或同类事件的原作 1–2 张，和成图并排看，写出**三处最大差异**，按这个顺序挑：人与物件比例；物件填满画面还是摆在中间；物件真实还是被重绘；人偶是色块还是精细；相机在场景里还是在外面。只写看见的，不打分。原作图片只在本机打开，不传给生成器。

## 商品保留项

图卡里列的每个保留部件记“保持／变化”，变化的写具体是什么变了。路线 B 可以另做阈值像素差，只用来看改动落在哪里，不作为“像素保护”的证明（输出会被缩放）；路线 A 只记目视。没有原图或小字看不清时不认证精确保真。

## 谁来判

- 助手的两问、并排和保留项记录是**记录**，不是验收。助手写了想法再自己读图，容易自我确认；连续几轮自评“更好”而用户说“更差”时，以用户为准，停下不再出图。
- 交用户看图时不加标题、不说明创意，只问一句“这是什么场景”。原话照录，不扩写成认可或否定。第一读落在物件之外的世界（赛道、泳池、检票口）记读法成立；落在商品名或物件本身的功能（打扫、洗碗、修插座）记成立但偏平；答不上来记未成立。人物大小、机位、风格不问用户。
- 用户第一读之后才可以给短标题；标题不能用来挽救画面本身没读出来的事。

## 之后做什么

| 结果 | 下一步 |
|---|---|
| 两问都过、用户认可 | 交付，记状态“用户认可”；不自动追加。 |
| 第一问失败 | 改法写进图卡：换部位或换事件（[一张图卡](picture-card.md)）。 |
| 第二问缺“人是零头” | 改法写进图卡：查“人高≈部件”写法和路线；不缩人、不改大小句。 |
| 第二问缺“物件是真的” | 改法：换路线 B（[制作路线](making-route.md)）。 |
| 第二问缺“相机在场景里” | 改法：路线 B 换底图；路线 A 改图卡第 1 条与提示第 4 句。 |
| 用户点名改某处 | 在那张上编辑一次，只改点名部分，说明编辑器会重绘周边。 |

“改法”只写进图卡与记录，下一张要用户说了才出（每案一张、失败不重试、追加张数要用户明确说，见 SKILL.md 闸门）。每轮只变一处；同一问题用户第三次说没过，停下交给用户决定方向。
